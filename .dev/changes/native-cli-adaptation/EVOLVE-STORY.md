# native-cli-adaptation 演进说明

本 change 起于 SiYuan v3.7.0 引入官方原生 `siyuan` CLI 后发生的全局命令冲突。调研确认，官方 CLI 覆盖大量数据操作并能离线运行，但本项目仍提供权限、审批、响应过滤、扩展和多工作区等不同价值。项目因此不放弃现有 HTTP API 底座，而是先建立无歧义入口，再选择性吸收新版官方能力。

方向经过讨论后收敛为两个 Agent 级工作包。N1 是最小可用交付：新增规范命令 `siyuan-cli`，同时保留 `siyuan` 兼容别名，使旧版 SiYuan 环境和既有调用仍有兼容路径；在 SiYuan 3.7.0 及以上环境中，文档和 Agent统一使用不会与官方命令混淆的 `siyuan-cli`。N1 可以独立发布，不等待后续工作。

N2 是后续能力补充：由一个 Agent整体评估最新原生 CLI、相关 HTTP API 和现有 tool 的差异，选择值得继承的能力。API 可达的功能继续优先走 guard 链，native 只考虑离线或原生独有的只读能力，写操作永不走 native。原生补充能力要求 SiYuan 3.7.0 及以上，保持可发现但在执行时做版本检查。由于本项目也保留 `siyuan` 别名，N2 还必须可靠区分官方原生二进制和本项目入口。serve 生命周期管理已经明确排除。

当前 N1 的需求和大致实现范围已经明确，节点工作区已建立，等待独立 Agent领取。N2 暂不实施，其具体能力清单和原生二进制定位策略留待该节点启动后继续澄清。
