# 无需 Agent 配合的其他进程归属判断办法

## 这项调查为哪个决定服务

`siyuan-cli` 的每次调用都是短命进程。两个独立调用需要判断自己是否来自同一个长期 Agent 进程，并把 workspace 绑定到该共同进程。

硬限制如下：

- 不能修改 Agent 运行框架；
- 不能要求 Agent 传身份、环境变量或令牌；
- 不能部署常驻中间服务；
- 多个独立 CLI 调用需要得到稳定一致的结果；
- 不能根据进程名称、命令行相似度或其他可能误绑的特征猜测身份。

当前主方向是读取父子进程关系。在 Windows + MSYS 中，候选做法是使用 MSYS 的逻辑父子关系到达外层 shell，再接上 Windows 原生关系。本调查独立检查是否还有更简单或更可靠的系统信息可以满足同样限制，防止过早锁定路线。

## 需要比较的候选信息

至少检查：

- Windows 父子进程关系；
- MSYS 逻辑父子关系与 Windows PID 的组合；
- Windows Job Object；
- 控制台进程列表或终端会话信息；
- Windows session id、process group 等分组信息；
- 进程继承的环境信息；
- 命名内核对象或可查询的父进程资源；
- WMI/ETW 等进程创建事件；
- 其他无需 Agent 主动配合的可靠系统关系。

对每条路线说明：

1. 短命 CLI 在启动后实际能读取到什么；
2. 两次独立调用是否会得到同一个、足够细的上级标识；
3. 是否会把多个无关 Agent 或终端误认为同一个；
4. 是否需要提前监听、保持句柄、常驻进程或 harness 配合；
5. 支持 Windows/MSYS 的实现和维护成本；
6. 无法判断时能否明确发现，而不是返回一个看似有效的结果。

## 不能做的事

- 不修改仓库文件；
- 不提出要求 Agent 配合的方案作为可行答案；
- 不用“有可能”代替对关键条件的说明；
- 不替用户决定产品应该支持哪些环境；
- 不假设子 Agent 知道主对话。

## 证据要求

关键判断应有官方文档、源码、可靠公开资料或本机验证支撑。没有直接证据时标明推断。无需穷举所有 Windows 技术，只保留可能改变路线选择的候选。

## 返回格式

1. 按可行性从高到低排列；
2. 每项写清能观察什么、缺什么、为何符合或不符合限制；
3. 最后给出：
   - 首选技术路线；
   - 值得保留的备用路线；
   - 可以明确排除的路线及理由。

只做技术判断，不做产品决策。
